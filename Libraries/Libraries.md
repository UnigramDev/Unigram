### Win2D

`Win2D/Microsoft.Graphics.Canvas.Interop.dll` is Win2D's own C# projection, rebuilt against CsWinRT 2.3.1. The copy inside the Win2D.uwp package is generated by CsWinRT 2.2.0, whose ABI stubs do not call `GC.KeepAlive` on the receiver: a Win2D object reachable only from a local can therefore be finalized while one of its own calls is still running in native code, and the D2D object dies under the callee. That is what took down `QrCode.CreateGeometry` on 12.10.4. 1.28.3 is the last Win2D.uwp release, so there is no package update to take instead, and `Telegram.Modern.csproj` and `Telegram.Win32.csproj` reference this file with `ExcludeAssets="compile;runtime"` on the package - `native` and `build` still carry `Microsoft.Graphics.Canvas.dll` and the winmd registration. `Telegram.csproj` needs none of this: .NET Native projects the winmd itself.

Only the CsWinRT version changes. The projection is pure generator output - upstream's `winrt/projection/winrt.projection.csproj` on branch `uwp/main` is the project below minus the winmd path, which they take from a ProjectReference to the native build. The rebuild has the same 369 public types as the shipped assembly and the same assembly references, bar `WinRT.Runtime 2.1.0.0` becoming `2.3.1.0`.

Generating the projection inside the app instead of as its own assembly does not work: its internal `IObjectReference` constructors are then visible to app code, and every `new CanvasPathBuilder(null)` becomes ambiguous.

To regenerate, drop this in an empty folder outside the repository as `Win2D.Projection.csproj`:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net8.0-windows10.0.19041.0</TargetFramework>
    <AssemblyName>Microsoft.Graphics.Canvas.Interop</AssemblyName>
    <LangVersion>latest</LangVersion>
    <UseUwp>true</UseUwp>
    <UseUwpTools>false</UseUwpTools>
    <DeviceType>UAP</DeviceType>
    <Platforms>AnyCPU</Platforms>
    <Platform>AnyCPU</Platform>
    <PlatformTarget>AnyCPU</PlatformTarget>
    <Version>1.28.3</Version>
    <InformationalVersion>1.28.3+cswinrt2.3.1</InformationalVersion>
    <IsAotCompatible>true</IsAotCompatible>
    <DisableRuntimeMarshalling>true</DisableRuntimeMarshalling>
    <GenerateDocumentationFile>false</GenerateDocumentationFile>
    <Deterministic>true</Deterministic>
    <NoWarn>$(NoWarn);CS0108</NoWarn>
  </PropertyGroup>

  <PropertyGroup>
    <WindowsSdkPackageVersion>10.0.19041.57</WindowsSdkPackageVersion>
    <CSWinRTIncludes>Microsoft.Graphics.Canvas;</CSWinRTIncludes>
    <CSWinRTWindowsMetadata>local</CSWinRTWindowsMetadata>
    <CsWinRTGenerateProjection>true</CsWinRTGenerateProjection>
  </PropertyGroup>

  <ItemGroup>
    <CSWinRTInputs Include="$(Win2DWinMD)" />
    <PackageReference Include="Microsoft.Windows.CsWinRT" Version="2.3.1" />
  </ItemGroup>

</Project>
```

`CS0108` is upstream's own suppression - `CanvasRenderTarget.CreateFromDirect3D11Surface` hides the `CanvasBitmap` overload it inherits. Then:

- `dotnet build -c Release -p:Win2DWinMD="%USERPROFILE%\.nuget\packages\win2d.uwp\1.28.3\lib\uap10.0\Microsoft.Graphics.Canvas.winmd"`
- Copy `bin\Release\net8.0-windows10.0.19041.0\Microsoft.Graphics.Canvas.Interop.dll` over the one here.

`Microsoft.Graphics.Canvas.Interop.xml` beside it is the package's own documentation file, copied unchanged so IntelliSense keeps working; it does not need regenerating unless the Win2D version changes.
